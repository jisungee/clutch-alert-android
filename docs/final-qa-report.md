# 최종 통합 QA 보고서 — 최신 인계 버전

검증일 2026-11-26, 목표 인계일 11/27. 인계 브랜치는 `codex/handoff-20261127`이다. 이 보고서를 포함한 최종 커밋을 기준으로 하며 정확한 SHA·최종 APK 해시는 Git 밖의 `build/handoff-20261127-final/ClutchAlarm-MVP-20261127-receipt.json`을 따른다. 커밋 자신을 문서 안에서 자기 참조하지 않는다. 이전 d6204eb 스냅샷 및 11/24 APK/검증 영수증을 이번 결과로 사용하지 않는다.

## 결론

새 설치 QA의 요청 흐름을 한 프로세스에서 완료했으며 **app_open1 / first_done1 / repeat_done2 / drop1**을 확인했다. 검증한 클라이언트 범위에서 인계를 막는 앱 결함은 발견하지 않았다. 실제 서버 인증/수집 성공이나 배포 서명 완료를 의미하지 않는다.

현재 모든 앱 구성은 실제 경기 기반 JSON10개/374개 이벤트만 포함한다. 합성8개는 테스트 전용이다. 홈 응원팀 바로가기, 날짜/상대, 전체 경기 경로 및 기존 디자인·알림 정책을 포함한 최신 상태를 검증했다.

## 실제 실행 순서

1. 새 설치 로그인 화면에서 회원가입 → 신규 계정 가입 성공 → 이메일이 채워진 로그인 화면 → 해당 계정 로그인 성공.
2. 한화 선택 → 알림 선택(기본15/16) → 선택한 설정 저장하기 → 한화 홈. 최초 저장과 홈 바로가기만으로 first_done을 기록하지 않는 것을 중간 로그로 확인했다.
3. ‘내 응원팀 경기 보러가기’로 한화–키움 상세 진입. LIST/NOT_APPLICABLE, 재생 대기 상태를 확인했다. 바로가기만으로 발송이나 알림 열람이 발생하지 않았다.
4. Android13+ 알림 권한 팝업에서 Allow를 눌러 허용한 뒤 1x 재생 → 일시정지. 발송 성공한 설치 순번1의 실제 시스템 알림을 눌러 상세 실제 표시 및 NEW를 확인했다.
5. 재개 → 설치 순번2 발송 → 일시정지 → 두 번째 실제 시스템 알림 탭 → 같은 경기 상세의 NEW 확인. 첫 번째는 경기 시작, 두 번째는 투수 기록이며 서로 다른 post ID다.
6. 뒤로 홈 → 알림 설정 → 저장 성공. repeat_done(settings_resave) 확인.
7. 알림 설정 재진입 → 전체 알림 토글을15/16에서16/16으로 조작 → 저장하지 않고 홈으로 나감. drop1 확인. 재진입해 실제 저장값15/16 유지까지 확인했다. 조작 없이 다시 나왔을 때 추가drop은 없었다.

전 과정에서 앱 프로세스를 종료/재실행하지 않았다. 스크린샷·기기 로그로 실행 순서와 상세 진입을 대조했다.
