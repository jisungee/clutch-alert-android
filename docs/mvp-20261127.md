# MVP-20261127 최종 클라이언트 인계 버전

브랜치 **codex/handoff-20261127**의 이 문서를 포함한 최종 HEAD가 인계 커밋이다. 이전 d6204eb 스냅샷 이후 실제 경기 기반 JSON10개/374개 이벤트, 합성8개 테스트 전용 분리, 홈 응원팀 바로가기와11/26 새 설치 통합 QA를 포함한다. 이전 이력을 보존하고 amend/rebase/force push로 버전을 바꾸지 않는다.

## 전달 산출물

Git에는 소스·원본 이미지·게임 JSON·테스트·정책·최신 문서를 전달한다. 다음은 Git 밖 별도 전달 파일이다.

| 파일 | 의미 |
|---|---|
| build/handoff-20261127-final/ClutchAlarm-MVP-20261127-QA.apk | 최종 커밋에서 빌드한 QA 디버그 APK |
| 같은 경로의 .apk.sha256 | 위 APK SHA-256 |
| 같은 경로의 ClutchAlarm-MVP-20261127-receipt.json | 정확한 커밋/브랜치·새 빌드·테스트·APK 감사·새 설치 QA 대조 |

커밋 SHA를 그 커밋의 문서에 자기 참조로 넣지 않는다. 외부 영수증의 commit과 `git rev-parse codex/handoff-20261127`을 대조한다. 기존 build/handoff 또는11/24 APK hash를 이번 파일에 재사용하지 않는다.

```powershell
git rev-parse codex/handoff-20261127
Get-FileHash build/handoff-20261127-final/ClutchAlarm-MVP-20261127-QA.apk -Algorithm SHA256
Get-Content build/handoff-20261127-final/ClutchAlarm-MVP-20261127-receipt.json
```

QA 패키지는 com.clutchalarm.app.behaviorqa이며 실제 사용자 앱과 분리된다. QA 가상 인증은 debug opt-in에만 존재한다. 일반/릴리스 인증은 실제 서버 연결 전까지 NOT_CONFIGURED이며 성공으로 우회하지 않는다. 릴리스는 unsigned, 배포/스토어 승인용 APK가 아니다.

## 재현 빌드

JDK17/SDK36. SDK 경로·서명 키는 로컬 환경에만 두고 Git/인계 ZIP에서 제외한다. Gradle Wrapper와 소스를 사용한다. 일반/QA의 출력 APK 이름이 같으므로 QA 직후 별도 보관한다.

```powershell
.\gradlew.bat -PbehaviorQa=true :app:assembleDebug :app:testDebugUnitTest --rerun-tasks
Copy-Item app/build/outputs/apk/debug/app-debug.apk build/handoff-20261127-final/ClutchAlarm-MVP-20261127-QA.apk
python tools/audit_apk.py build/handoff-20261127-final/ClutchAlarm-MVP-20261127-QA.apk --expect-qa
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:assembleRelease :app:testReleaseUnitTest --rerun-tasks
python tools/audit_apk.py app/build/outputs/apk/debug/app-debug.apk
python tools/audit_apk.py app/build/outputs/apk/release/app-release-unsigned.apk --release
```

필요하면 `-Dorg.gradle.jvmargs="-Xmx1536m -XX:MaxMetaspaceSize=512m" --max-workers=1`을 추가한다. 구성별149개 테스트를 새로 실행한다. 모든 APK는 실제 경기10개만 포함하며 테스트 전용 합성8개는 패키징하지 않는다. 실제 경기 JSON은 줄바꿈 자동 변환 없이 원본 bytes를 보존한다.

## 서버 담당자의 남은 작업

1. AuthenticationRepository의 회원가입·로그인·현재 계정·세션 복원/갱신·로그아웃·회원 탈퇴를 실제 인증 명세로 구현해 productionAuth 공급 위치에 연결한다.
2. BehaviorEventRecorder에 event_id·발생 시각·영속 outbox·재시도/ACK·서버 멱등 집계를 연결한다. 이벤트 발생 기준과 repeat_done의 notification_open/settings_resave action을 유지한다.
3. 토큰 수명/회전·폐기·탈퇴 재인증/멱등성·익명 app_open/계정 연결 정책을 확정한다. 현재 코드의 로그 UUID/알림 post ID/경기 event_id를 수집 event_id로 혼용하지 않는다.
4. 경기·응원팀·알림 설정과 알림 발송은 로컬 MVP 범위다. 이후 추가 데이터/판독 표현·정정 대상·안정적인 선수 ID는 별도로 검증한다.
5. 실제 서버 연결 후 통합/오프라인/중복/오류 QA를 수행하고 이후 배포 서명·버전 상승·스토어 이관을 준비한다.
