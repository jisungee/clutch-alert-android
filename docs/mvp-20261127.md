# MVP-20261127 최종 클라이언트 인계 버전

버전명 **MVP-20261127**, 브랜치 **codex/handoff-20261127**. 이 문서를 포함한 브랜치 HEAD를 최종 인계 커밋으로 식별한다. 이전 이력을 보존하며 amend/rebase/force push로 스냅샷을 바꾸지 않는다. 별도 체크아웃의 추적 파일이 깨끗한 상태에서 일반·QA·릴리스 빌드와 단위 테스트를 실행한다.

## 전달 실행 파일·검증 영수증

저장소 루트의 다음 파일은 Git에 넣지 않고 별도 전달한다.

| 파일 | 의미 |
|---|---|
| `build/handoff/ClutchAlarm-MVP-20261127-QA.apk` | 확정 커밋의 별도 체크아웃에서 빌드한 QA 디버그 APK |
| `build/handoff/ClutchAlarm-MVP-20261127-QA.apk.sha256` | 위 APK의 SHA-256과 파일명 |
| `build/handoff/ClutchAlarm-MVP-20261127-receipt.json` | 확정 커밋 SHA·브랜치·원격 대조·별도 체크아웃·빌드/테스트·APK 감사 결과 |

커밋 SHA를 그 커밋의 문서 안에 자기 참조로 넣지 않는다. 최종 SHA는 `git rev-parse HEAD`와 검증 영수증을 대조한다. APK 해시는 이 문서의 이전 단계 해시가 아니라 **이름이 일치하는 최종 APK의 sidecar/영수증**으로 확인한다. 푸시 후 `git ls-remote origin refs/heads/codex/handoff-20261127` 결과가 영수증의 SHA와 같아야 한다.

```powershell
git rev-parse HEAD
Get-FileHash build/handoff/ClutchAlarm-MVP-20261127-QA.apk -Algorithm SHA256
Get-Content build/handoff/ClutchAlarm-MVP-20261127-QA.apk.sha256
Get-Content build/handoff/ClutchAlarm-MVP-20261127-receipt.json
```

APK는 테스트용 패키지 `com.clutchalarm.app.behaviorqa`이며 QA 가상 인증을 포함한다. 실제 운영 로그인이나 서버 삭제를 제공하지 않는다. 일반 사용자 앱을 덮어쓰지 않는다. 릴리스는 QA 코드/문구·진단 태그를 제외하지만 현재 unsigned이며 배포 파일로 취급하지 않는다.

## 별도 체크아웃 재현

확정 커밋을 별도 체크아웃한 후 JDK17·SDK36을 사용한다. SDK 경로는 그 체크아웃의 무시된 `local.properties` 또는 로컬 환경으로만 공급한다. 원본 프로젝트의 빌드 폴더·로컬 앱 데이터·키를 복사하지 않는다. 기본 디버그 서명은 개발 PC의 기존 Android debug keystore를 사용하며 키 파일을 전달하지 않는다.

```powershell
# 일반 디버그 → 결과 검사/보관
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest --rerun-tasks
python tools/audit_apk.py app/build/outputs/apk/debug/app-debug.apk

# QA 디버그 → 이 시점의 APK를 최종 파일명으로 복사
.\gradlew.bat -PbehaviorQa=true :app:assembleDebug :app:testDebugUnitTest --rerun-tasks
python tools/audit_apk.py app/build/outputs/apk/debug/app-debug.apk --expect-qa

# 일반 릴리스
.\gradlew.bat :app:assembleRelease :app:testReleaseUnitTest --rerun-tasks
python tools/audit_apk.py app/build/outputs/apk/release/app-release-unsigned.apk --release
```

환경 메모리 제한 시 `-Dorg.gradle.jvmargs="-Xmx1536m -XX:MaxMetaspaceSize=512m" --max-workers=1`을 덧붙인다. 디버그 출력 파일명은 일반/QA가 같으므로 각 빌드 직후 감사·테스트 집계·복사를 수행한다. 모든 구성의 현재 테스트 목록은 134개이며 실제 결과·실행 여부는 영수증으로 확인한다.

## 기능과 증거 기준

- 최신 앱 기능·디자인·로고·알림 정책·인증 경계는 [README](../README.md)와 [통합 서버 인계](server-handoff.md)를 따른다.
- [최종 통합 QA](final-qa-report.md): 같은 프로세스에서 app_open 1 / first_done 1 / repeat_done 2 / drop 1, 실제 시스템 알림 순번1·2 열람, 자동 로그인·로그아웃·QA 탈퇴, 기존 설치 업데이트 데이터 유지.
- API36 에뮬레이터에서 시스템 스플래시·권한 허용/거부/재허용을 실제 확인했다. 정확한 API31/33·다른 제조사·TalkBack·실제 서버/스토어 이관은 미검증이다.
- 원본 이미지13개를 보존하며, 승인된 4구단 디자인을 포함한 10구단 홈·기본/1.3배 증거는 [최종 홈](home-gradients-final.md)에 있다.
- Git 전달 경로는 [정확한 목록](handoff-files.txt), 제외 기준은 [파일 분류](handoff-files.md)다. hprof·구형 APK·캐시·로컬 SDK 설정·서명 키·기기 백업은 포함하지 않는다. QA 가상 자격 증명은 테스트 소스와 재현 문서에만 존재하며 실제 자격 증명과 구분한다.

## 서버 담당자의 남은 작업

1. `AuthenticationRepository`의 가입·로그인·현재 계정·세션 복원/갱신·로그아웃·회원 탈퇴를 실제 인증 명세로 구현하고 productionAuth 공급 지점에 연결한다.
2. `BehaviorEventRecorder`에 event_id·발생시각·영속 outbox·재시도·ACK·서버 멱등 집계를 연결한다. 발생 조건과 repeat_done action 두 가지를 유지하고 설정 저장·경기 재생을 네트워크에 종속시키지 않는다.
3. 토큰 수명/회전·세션 폐기·탈퇴 재인증/멱등성·익명 app_open과 계정 연결을 확정한다. INTERNET 권한 및 네트워크 의존성은 실제 연결 단계에서 추가한다.
4. 원본 경기 JSON이 오면 전체 플레이 연속성·선수 ID·판독 정정 대상·시간 단위·B/S를 재검증한다. 경기·응원팀·알림 설정은 현재 로컬이며 서버 동기화/FCM은 이번 인계 범위가 아니다.
5. 실제 서버 연결 후 통합/오프라인/중복/오류 QA를 수행하고, 이후 배포 서명·버전 상승·스토어 업데이트를 준비한다.
