## QA 재현 순서

### 설치와 로그

연결 기기 1대 기준 PowerShell 명령이다. 여러 대면 `adb -s <serial>`을 사용한다.

```powershell
.\gradlew.bat -PbehaviorQa=true :app:assembleDebug
adb devices -l
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell pm clear com.clutchalarm.app.behaviorqa
adb shell am start -n com.clutchalarm.app.behaviorqa/com.clutchalarm.app.MainActivity
adb shell pidof com.clutchalarm.app.behaviorqa
adb logcat --pid <QA_PID> -v threadtime 'ClutchBehavior:D' 'ClutchNotificationPost:D' 'ClutchNotificationOpen:I' '*:S'
```

`<QA_PID>`는 pidof 결과로 바꾼다. 새 프로세스로 실행하면 PID와 app_open 구간도 새로 잡고 과거 테스트 로그와 합산하지 않는다.

### 정상 첫 이용 → 첫 알림

1. **SSG 랜더스 → 다음 → 기본 15/16 유지 → 선택한 설정 저장하기**. 홈으로 이동하며 first_done은 0이다. 계정 입력은 없다.
2. **모의 경기 보러가기 → 모의 경기 · 일반**. 재생 전 안내의 **부산 웨이브스**를 선택한다. 저장된 응원팀 SSG는 유지된다.
3. 시스템 알림이 ON인지 확인한다. OFF면 안내의 **시스템 알림 설정 열기**에서 앱 알림과 ‘모의 경기 알림 (팝업)’을 켜고 돌아온다. Android 13+ 권한 요청이 보이면 허용한다.
4. **1x → 모의 경기 재생하기**. 경기 시작 알림이 나오면 일시정지한다. `ClutchNotificationPost`에서 설치 순번 1인지 확인한다. 첫 알림만 검사하려면 3초 뒤 다음 이벤트 전에 일시정지한다.
5. 화면 위에서 알림창을 내려 **ClutchAlarm QA의 ⚾ 경기 시작**을 누른다. 상세가 실제 표시되고 `NEW`, first_done 1건인지 확인한다. 목록 카드나 앱 내 ‘본문 보기’로 대신하지 않는다.
6. 목록 직접 진입·동일 POST_ID 재전달로 first_done이 늘지 않는지 확인한다. 회전 검사는 기존 보고서와 함께 추가 확인할 수 있다.

동일 ID 재전달 값은 이번 실제 발송 로그에서 가져온다.

```powershell
adb shell am start --activity-single-top -n com.clutchalarm.app.behaviorqa/com.clutchalarm.app.MainActivity -a com.clutchalarm.app.OPEN_GAME --es com.clutchalarm.app.GAME_ID mock-001 --es com.clutchalarm.app.POST_ID <실제_POST_ID> --el com.clutchalarm.app.POST_SEQUENCE 1 --es com.clutchalarm.app.POST_SEQUENCE_SCOPE_ID <실제_설치_ID> --es com.clutchalarm.app.POST_SEQUENCE_SCOPE INSTALLATION
```

### 알림 OFF → 재생 → 다시 ON

설치 1번 검사와 이어서 보려면 위 순서 2 직후, **첫 성공 발송 전에** 실시한다.

1. Android 설정 → 애플리케이션 → **ClutchAlarm QA** → 알림 → **알림 받기 OFF**. 앱으로 돌아온다.
2. 상세의 OFF 안내와 설정 버튼, 재생 버튼을 확인한다. **10x → 모의 경기 재생하기**로 끝까지 재생한다. first_done·repeat_done(notification_open)은 0이고 성공 순번을 소비하지 않아야 한다.
3. 상세의 **시스템 알림 설정 열기 → 알림 받기 ON → 뒤로**. 정상 안내로 바뀌는지 확인한다.
4. **1x → 처음부터 다시 재생** 후 정상 순서 4~6처럼 실제 첫 시스템 알림을 연다. 첫 성공 발송은 여전히 설치 1번이어야 한다.

## 남은 확인

- **Android 13 이상 POST_NOTIFICATIONS 런타임 거부**는 API 29 기기로 검증하지 않았다. Android 10 앱 알림 OFF 결과를 런타임 권한 거부 결과로 대체하지 않는다.
- 서버 수집·재시도는 명세 확정 전까지 보류. 로그는 서버 저장 증거가 아니다.
- 2번→1번 열람, 설정 repeat_done/drop, 프로세스 종료 후 순번 연속성 등 이전 결과는 [행동 이벤트 보고서](behavior-events-report.md)와 [마이페이지 보고서](mypage-report.md)를 참고한다.
