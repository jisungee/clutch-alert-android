# 응원팀·알림 선택과 첫 이용 흐름

## 구현

- 최초 설치: 저장소 로드 → 응원팀 10개 구단 선택 → 카테고리/세부 알림 선택 → 선택한 설정 저장하기 → 홈. 인증·행동 이벤트는 추가하지 않는다.
- 첫 저장은 preferred_team_id, 16개 알림 설정, hide_when_losing, onboarding_completed를 기존 DataStore 한 번의 edit로 저장한다. 성공한 반환값만 실제 발송 설정에 사용한다.
- 설정 화면에는 saved와 별도의 editor.draft가 있다. 카테고리 ON은 소속 항목 전체 ON, OFF는 전체 OFF다. 전체 조작도 draft에만 적용한다. 상세에서 뒤로는 카테고리로 복귀하며 draft를 유지한다. 설정 루트에서 뒤로는 전체 draft를 폐기한다.
- 실패 시 저장 전 active 설정과 완료 상태는 유지하고 draft와 오류를 표시하여 같은 버튼으로 재시도한다. 저장 대기 중 편집·뒤로·중복 저장은 막는다.
- 응원팀 변경 단독 화면도 명시적으로 저장한다. 알림 설정에서 팀 변경으로 이동했다면 같은 draft로 돌아와 함께 저장한다.
- 첫 이용 중 앱을 종료하면 다음 실행에서 미완료 상태로 팀 선택부터 다시 시작한다. 토글을 누른 것만으로 완료를 기록하지 않는다.
- 저장된 응원팀이 없는 모의 경기는 저장 팀을 자동 변경하지 않는다. 기존 상세의 경기별 임시 알림 관점은 명시적으로 구분한다. 일반 경기 진입은 저장된 팀을 기본값으로 사용한다.
- 첫 이용 미완료 중 알림 진입은 보류하여 설정 성공 후 요청한 상세로 연결한다.

## 시안 카테고리 매핑

| 카테고리 | 현재 토글 | 비고 |
| --- | --- | --- |
| 경기 상황 및 득점 흐름 | GAME_START, INNING_CHANGE, GAME_END, ON_BASE, OPPONENT_ON_BASE, SCORE, HOME_RUN, LEAD_CHANGE, CONCEDE, BIG_INNING | 경기 시작/종료도 흐름에 포함. 10개 |
| 돌발 변수 및 위기, 판정 | VIDEO_REVIEW, INJURY, BENCH_CLEARING | 판정·부상·돌발 상황. 3개 |
| 선수 기용 및 경기 데이터 분석 | PITCHER_CHANGE, PITCHER_STAT | 투수 기록은 분석에 배치. 2개 |
| 주요 기록 달성 및 선수 퍼포먼스 | DEFENSE_HIGHLIGHT | 호수비를 퍼포먼스로 해석. 1개 |
| 구단 엔트리 및 팬 개인화 활동 | 없음 | 제공 항목 없음 안내, 비활성 |
| 경기장 직관 편의 | 없음 | 제공 항목 없음 안내, 비활성 |
| 경기 종료 후 리그 정보 및 복기 | 없음 | 단순 경기 종료는 흐름에 매핑. 복기·리그 정보 기능은 없음 |

16개를 중복 없이 한 번씩 배치한다. 모호한 항목에 새 알림 판정이나 가상의 설정을 추가하지 않는다. 지는 중 숨기기는 카테고리 밖 전역 옵션이며 기존 경기별 숨김 정책은 보존한다.

## 기존 사용자 이관

기존 notification_preferences 저장소와 키를 유지한다. 신규 완료 키가 없고 예전 initialized/disabled/hide 키가 있으면 기존 사용자로 간주해 첫 이용을 완료한 것으로 읽는다. 알림 값과 지는 중 숨기기를 그대로 보존하며 팀은 미선택으로 둔다. 새 완료 키가 명시적으로 false라면 예전 키가 생겨도 완료로 바꾸지 않는다. 상대 출루 기본 OFF 및 이닝·동점의 기존 공유 토글 이관도 유지한다.

## 검증

- 첫 저장 전 쓰기 0회, 성공 후 완료·팀·알림 동시 반영, 새 ViewModel에서 홈 진입.
- DataStore 파일을 닫고 새 저장소로 다시 열어 팀/알림/완료/전역 옵션 보존.
- 첫 이용 중단 후 재실행은 미완료. 설정 편집 후 저장 없이 이탈하면 팀·토글·전역 옵션 모두 이전 값.
- 실패 후 draft 유지·active 불변·완료 false, 재시도 성공. 저장 대기 중 active 불변·중복 저장 및 뒤로 차단.
- 재생 중 편집값은 미적용, 명시적 저장 후 이후 이벤트에 적용. 과거 필터된 이벤트 재발송 없음.
- 무관한 모의 경기 진입·임시 관점 선택으로 저장된 팀을 바꾸지 않음. 팀 변경 저장은 상세 기본 관점에도 반영.
- 기존 사용자 키로 이관해 알림·전역 옵션을 그대로 보존.
- 기존 16개 판정 정책 및 ⑥→⑦→⑧/알림 진입 회귀 테스트 유지.

빌드: `./gradlew.bat :app:assembleDebug :app:testDebugUnitTest` 성공. 단위 테스트 80개 통과(실패·오류·스킵 0), 테스트는 새로 실행했다. `git diff --check`도 통과했다.

## 실기기 검증 완료

사용자가 잠금을 해제한 뒤 최종 APK를 업데이트 설치하여 확인했다. 검증 시작 시 기존 DataStore 설정 파일이 없는 상태였고 앱의 최초 응원팀 선택 화면이 표시되었다.

- 10개 구단 표시, SSG 선택 후 다음 활성화, 알림 선택/세부 화면 이동 확인.
- 전체 토글 조작 후 저장 전 설정 파일이 생성되지 않음을 확인.
- 경기 시작 1개만 선택해 첫 저장 → SSG가 표시된 홈 진입. 앱 강제 종료 후 재실행해 첫 이용 화면 대신 홈으로 진입 확인.
- 알림 설정에서 전체 ON으로 편집하고 저장 없이 시스템 뒤로 → 재진입 시 기존 1/16 유지 확인.
- 전체 ON을 명시적으로 재저장 → 종료·재실행 → 설정 화면 16/16 확인.
- 응원팀 변경 화면에서 LG 선택 후 미저장 뒤로 → 홈 SSG 유지 확인. KIA로 변경 저장 → 홈 KIA 표시 확인.
- 홈 → 8개 모의 경기 목록 → 부산/서울 상세 진입. 해당 경기에는 KIA가 없지만 저장된 KIA가 유지됨을 상세와 홈에서 확인.
- 상세 재생 → 일시정지 → 재개 → 10배속 → 재생 완료 확인. 시스템 뒤로 두 번으로 목록 → 홈 복귀 확인.
- 화면 캡처로 응원팀 선택·홈·상세의 잘림 없는 기본 표시를 확인했다.

검증 종료 시 앱을 중지하고 이번 테스트에서만 생성한 `files/datastore/notification_preferences.preferences_pb` 한 파일을 제거했다. 앱 전체 데이터 초기화는 하지 않았다. 재실행하여 팀 선택 미완료/선택 없음 상태로 복원했음을 확인했다. 임의의 테스트 팀/알림 값을 사용자 설정으로 남기지 않았다.

추가 기기 검증: 저장 실패 및 디스크 오류, 기존 사용자 설정 이관, 회전·글자 확대, 시스템 알림창 탭. 저장 실패·기존 설정 이관은 80개 JVM 테스트 중 해당 테스트와 임시 DataStore 재개방으로 검증했다. 이 실기기 확인에서는 소스 수정 없이 보고서만 갱신했으므로 빌드·테스트를 반복하지 않았다.
