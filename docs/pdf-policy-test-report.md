# 새 PDF 정책 적용 검증

## 재생과 스키마

- 기존 7개와 새 `pdf-snapshot-test`를 목록에서 선택하여 ViewModel을 통해 끝까지 재생하고 reset/close를 검증한다.
- 새 예시는 모든 플레이를 포함한 1이닝 단축 합성 경기다. 13개 이벤트이며 실제 경기 기록이 아니다.
- initial_state를 첫 before로, 직전 after를 다음 before로 사용한다. 원본 이름과 play_actor를 보존하고 current_batter는 결과 상태로 표시한다.
- delay_sec 누적, B/S null, 판독의 구조화된 점수 3→2와 아웃 1, 종료 상태를 검증한다.

## 역전 홈런 (실제 ViewModel 발송기 호출 수)

| HOME_RUN | SCORE | LEAD_CHANGE | 해당 플레이 발송 |
| --- | --- | --- | --- |
| OFF | OFF | OFF | 0 |
| ON | OFF | OFF | 1 |
| OFF | ON | OFF | 1 |
| OFF | OFF | ON | 1 |
| ON | ON | OFF | 1 |
| ON | OFF | ON | 1 |
| OFF | ON | ON | 1 |
| ON | ON | ON | 1 |

16개 전체 ON도 1건이다. 매 경우 전체 경기에서 이벤트 ID 중복 발송이 없음을 확인한다.

## 재개 플레이의 제목·유형

| 켠 토글 | 제목 | 유형 |
| --- | --- | --- |
| 홈런만 | 홈런 | HOME_RUN |
| 득점만 | 득점 | RUN_SCORED |
| 역전만 | 역전 | COMEBACK |
| 셋 다 | 역전 홈런 | COMEBACK |

0:2→2:2→3:2와 직접 역전 홈런 양쪽에서 검증한다. 알림은 한 플레이 최대 1건이다. 두 항목 조합은 홈런+득점→홈런, 홈런+역전→역전 홈런, 득점+역전→역전이다.

## 필터와 정정

- 상대 출루 기본 OFF. 우리 출루 ON만으로 상대 출루를 보내지 않는다. 우리 출루 OFF + 상대 출루 ON이면 상대 출루를 보낸다.
- SCORE + ON_BASE 두 개만 ON, LEAD_CHANGE OFF 상태에서 뒤처짐→동점→앞섬: 뒤처진 득점·동점 득점·동점 출루는 숨김, 다시 앞서는 득점만 발송한다. 숨긴 이벤트는 다시 처리하지 않는다.
- HOME_RUN + SCORE만 ON, LEAD_CHANGE OFF의 역전 홈런은 즉시 한 건 발송 가능하다. 재개 판정은 토글과 무관하며, 이번 경기에서 뒤처진 이력과 플레이 후 점수가 다시 앞섰는지로 결정한다.
- GAME_END는 뒤처짐이 이어지는 동점/패배 종료 모두 숨긴다. 뒤처진 적 없는 동점 종료는 구독 ON일 때 발송한다.
- 3점에서 빅이닝, 추가 득점 중복 없음. 판독으로 3→2 취소 후 다시 3점이 되어도 같은 반이닝에는 재발송하지 않는다. 다음 공격 반이닝에서는 다시 판정한다.
- 점수 감소는 판독 번복에만 허용한다. 판독은 득점·실점으로 매칭하지 않는다.
- 상대 출루와 지는 중 숨기기 설정은 DataStore를 닫고 다시 열어 유지됨을 검증한다.

## 실행 및 한계

`./gradlew.bat :app:assembleDebug :app:testDebugUnitTest` 실행 결과 BUILD SUCCESSFUL, 단위 테스트 65개 통과(실패·오류·스킵 0)다. 마지막 실행에서 testDebugUnitTest가 새로 실행되었다. 테스트는 Android 시스템이 아닌 발송기 경계까지 검증하며 실제 알림창·권한·알림 탭은 기기 확인이 필요하다. ADB 서버는 시작했으나 연결 기기가 없었다.
